1. One final score ledger with bonuses, caps and explicit legacy rounding reconciliation; qualifier-safe discount labels; full idea provenance and caveats.
2. Separate evaluation rates, specific offers, ongoing promotions, leads and inspiration. Expandable source/terms/price context, unknown fields, observation versus verified-terms distinction, conservative duplicate flags and exact-only backend deduplication.
3. Search, destination/location, known-date, SGD/night and offer-type filters; score/freshness/date/price sort; all hotel results available when matching the dashboard snapshot; explicit subset warnings. Browser-only save/dismiss/restore, with retained saved snapshots and storage-failure handling.
4. Health sidecar, last attempt/success, partial failures and no-result states; source observation dates retained on fallback; failed hotel/empty-hotel guard intact; health-only commit on scan failure, per-file atomic JSON replacement and workflow concurrency. All times use Singapore explicitly.
5. Compact desktop cards/header, responsive CSS for 3/2/1 columns, expandable details, visible keyboard focus, labelled native dialog and an old-layout link sharing the corrected behavior. No framework rewrite.

No committed generated data, hotel history, provider limits, secrets or accounts were changed. No provider scans or quota-consuming test workflows were run. Main was not merged and the site was not deployed.

## Remaining limitations

Evaluation/net hotel rates are not consumer quotes; hotel history may compare different cheapest room/board/cancellation conditions. Merchant terms, expiry and stock remain incomplete. A successful fetch can still produce zero records because a source changed HTML. Duplicate detection is advisory and conservative. Browser lists do not sync. Workflow/infrastructure failures before status writing, cancellation or Git-push failure cannot be reliably surfaced in the static health file. Existing records cannot retrospectively supply missing attempt/verification history.
